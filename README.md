# docx-to-asciidoc-converter

Converts the Word documents in docx format that are located in the source folder to AsciiDoc and publishes them as an HTML site using [Antora](https://antora.org).

## Requirements

- [pandoc](https://pandoc.org/) (used for the DOCX → AsciiDoc conversion)
- Node.js 18+ and npm (used for Antora)

## Quick start

```sh
npm install
npm run build
```

`npm run build` runs the whole pipeline:

1. **`convert`** – pandoc converts the DOCX in `source/` to AsciiDoc in
   `destination` and extracts the embedded images.
2. **`split`** – `build-antora.js` splits the single AsciiDoc file into one
   page per top-level chapter under `antora/modules`, copies the
   images into `antora/modules`, rewrites cross-references, and
   generates `nav.adoc` and a landing page.
3. **`build:site`** – Antora renders the AsciiDoc to HTML in `build/site/`.
4. **`verify`** – `verify-links.js` checks that every anchor and
   cross-reference resolves to a real target in the generated HTML.

To preview the result with a local web server:

```sh
npm run preview
```

## Individual steps

| Command              | Description                         |
|----------------------|-------------------------------------|
| `npm run convert`    | DOCX → AsciiDoc into `destination`  |
| `npm run split`      | AsciiDoc → Antora component pages   |
| `npm run build:site` | Antora → HTML in `build/site/`      |
| `npm run verify`     | Check anchors and cross-references  |
| `npm run serve`      | Serve `build/site/` on a local port |

## Project layout

```
source/                         # input DOCX (source of truth)
destination/                    # intermediate AsciiDoc + extracted media
antora/
  antora.yml                    # Antora component version descriptor
  modules/ROOT/
    nav.adoc                    # generated site navigation
    pages/                      # one .adoc page per chapter (generated)
    images/                     # images extracted from the DOCX (generated)
antora-playbook.yml             # Antora site configuration
convert-to-asciidoc.sh          # DOCX → AsciiDoc (pandoc)
build-antora.js                 # AsciiDoc → Antora pages
verify-links.js                 # link/anchor checker
```

## Notes

- **Generated files.** Everything under `antora/modules` and
  `destination` is regenerated by the build; edit the source DOCX instead of
  editing them by hand.
- **Git repository required.** Antora only accepts a content source that lives
  in a git repository, which is why this project is a git repo. The playbook
  uses `branches: HEAD`, so uncommitted changes are picked up automatically (Antora's "author mode").
- **Heading IDs.** The playbook sets `idprefix: ''` and `idseparator: '-'` so
  that HTML anchors match the slugs generated by `build-antora.js`. Changing
  these would break the internal links.
- **Section numbering.** Chapter (page) titles keep the fixed numbers from the
  original Word document (1-8), which are taken from the table of contents that
  pandoc leaves in the converted file. The sections *within* a page are
  numbered automatically by Asciidoctor's `sectnums` attribute, which restarts
  at 1 for every page, so a page's first section is `1`, its subsections are
  `1.1`, `1.2`, and the next section is `2`.
- **Cross-references.** Links that pointed at Word bookmarks (`_Toc…`/`_Ref…`)
  or at figure captions cannot be resolved after conversion and are reduced to
  their plain link text.
